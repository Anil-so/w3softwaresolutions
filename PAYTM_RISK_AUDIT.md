# Paytm UPI Risk Policy Diagnostic Audit & Technical Report

This document presents a technical diagnostic audit analyzing the Paytm error message:
**`"Payment failed as per UPI risk policy"`**

---

## 1. UPI Intent Request Audit

Below is the exact payload generated by the application for the test transaction:

```text
upi://pay?pa=khadoliyavikash-1%40okhdfcbank&pn=W3+Software+Solutions&am=1.00&cu=INR&tn=Registration+Fee+-+Order+%23W3-2026-000001&tr=TR_1724384920_ABC
```

### Parameter Breakdown
- `pa`: `khadoliyavikash-1@okhdfcbank` (Payee VPA)
- `pn`: `W3 Software Solutions` (Payee Name passed in intent)
- `am`: `1.00` (Transaction amount in INR)
- `cu`: `INR` (Currency code)
- `tn`: `Registration Fee - Order #W3-2026-000001` (Transaction Note)
- `tr`: `TR_1724384920_ABC` (Merchant Transaction Reference)
- `mc`: *Omitted* (No Merchant Category Code)

## 3. Paytm UPI Risk Policy Analysis

Paytm, Google Pay, PhonePe, and NPCI enforce automated risk and fraud detection algorithms to protect users from phishing and unauthorized commercial collections on personal VPAs.

### Key Factors Triggering `"Payment failed as per UPI risk policy"`:

1. **Payee Name Mismatch (`pn` vs Registered VPA Name)**:
   - The intent payload declares `pn=W3 Software Solutions`.
   - When Paytm queries NPCI's Central Mapper for `khadoliyavikash-1@okhdfcbank`, the bank returns **`Vikash Saini`**.
   - Paytm's risk engine detects that an entity name (`W3 Software Solutions`) is attempting to collect funds on a personal VPA registered to an individual (`Vikash Saini`). This discrepancy is flagged as a potential phishing or impersonation risk.

2. **Personal VPA (P2P) Used for Commercial Web Collection**:
   - The VPA handle `@okhdfcbank` belongs to a personal consumer account (Peer-to-Peer / P2P).
   - Under NPCI regulations, personal VPAs cannot be used for automated web intent collection with commercial transaction notes (`tn=Registration Fee...`) without a registered acquiring bank Merchant ID (`mid`) and Merchant Category Code (`mc`).

3. **Missing Merchant Category Code (`mc`)**:
   - Automated commercial payments require a valid 4-digit Merchant Category Code assigned by an acquiring bank (e.g. `mc=5734` for Computer Software).
   - Without an `mc` parameter, Paytm treats the transaction as an unverified P2P transfer.

4. **Automated P2P Velocity & Fraud Rules**:
   - Repeated web-initiated Intent requests for ₹1.00 on a personal VPA trigger automated velocity controls designed to block micro-transaction testing or collect-request spamming.

## 5. Legitimate Production Solution & Recommendation

To eliminate UPI risk policy declines and operate a production-ready payment flow, the legitimate business solution is:

1. **Onboard an Official Business / Merchant UPI VPA**:
   - Register a Merchant UPI Account with a bank (e.g., HDFC Merchant Banking, Paytm Business, or PhonePe Business).
   - Obtain a verified business VPA (e.g., `w3software@hdfcbank` or `w3software@paytm`).
2. **Matching Legal Entity Identity**:
   - The merchant account will be registered under the official business name **`W3 Software Solutions`**.
   - NPCI's Central Mapper will return `W3 Software Solutions` when queried by any UPI app.
3. **Inclusion of Merchant Category Code (`mc`) & Merchant ID (`mid`)**:
   - The acquiring bank will assign a valid `mc` (e.g. `mc=5734`) and `mid`.
4. **Whitelisted Web Intent Collection**:
   - Verified merchant VPAs are whitelisted across Paytm, Google Pay, PhonePe, and BHIM for web intent collections.
